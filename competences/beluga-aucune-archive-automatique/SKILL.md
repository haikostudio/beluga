# beluga-aucune-archive-automatique

## Procédure

1. DEUX RÈGLES DISTINCTES (DEC-346, affinée le 12/10/2026). Tableau d'un projet : une carte mise en ligne passe seule en `archived` (`deploy.ts` → `archiveCard` quand `etape.clot` ; `ETAPE_DEV.arrivee = 'archived'`). Page « Tableaux de bord » : l'archivage AUTOMATIQUE ne range rien (la carte reste dans « Terminer »), l'archivage À LA MAIN range tout de suite.
2. Cartes sans code (démon : `rangerCarteDAgent`, `poserLEtat` des moteurs ajoutés, agents attitrés via `COLONNE_DE_FIN_D_UN_AGENT_ATTITRE`, mère via `colonneDeLaMere`/`suivreLaMere`) : `archived` avec `doneAt`/`archivedAt`, JAMAIS de `deployedAt` (sinon le message suivant du chat Studio ouvre une nouvelle carte, capture #c201). Elles appellent `rangerLaCarte` SANS le quatrième paramètre : pas de rangement.
3. TÂCHE RENDUE SANS AUCUNE MODIFICATION (décision du 12/11/2026) : `issueDeFinDeTour` (shared/src/suivi-colonne.ts) rend `COLONNE_D_UN_RENDU_SANS_CODE` (`archived`) + `RAISON_RENDU_SANS_CODE` pour la trace « non » sans code déjà enregistré. `carteApresFinDeTour` (server/src/deplacement-carte.ts) pose `doneAt` et efface l'attente ; il garde `to_deploy` (sans phrase) si la carte porte une veille `attend_deploiement` (elle ne s'arme qu'en ligne), et une étape de suite reste dans son groupe (`etapeRetenueEnFinDeTour` accepte `archived`). Le runtime note la carte (`carteAArchiverApresLeTour`) et appelle `archiveCard` APRÈS `retirerLeTourVivant` — `archiveCard` refuse un agent encore vivant —, par import dynamique (archive.ts importe runtime.ts). Restent en `to_deploy` : trace « oui », code déjà enregistré, « ailleurs », « inconnue », balayage des cartes oubliées (`issueDeCarteOubliee`, aucun constat possible).
4. Page centrale : `estATerminer` = carte finie (`to_deploy` ou `archived`) sans `rangeeTableauDeBordAt` ; `estRangee` = finie avec. Le champ est une vraie colonne (`rangee_tableau_de_bord_at`, migration 115 qui pose rangées toutes les cartes déjà archivées).
5. `estATerminer`/`estRangee`/`placeDeLaFamille` (shared/src/en-route.ts) et la requête SQL `famillesParDerniereAction` (server/src/store.ts : `candidate`, `a_terminer`, `archivee`) changent ENSEMBLE.
6. Le rangement se pose ou s'efface à DEUX endroits seulement. (a) `card.rangerTableauDeBord { ids, range }` (ws.ts) : « Tout archiver » et glisser, sans changer de colonne ni `deployedAt`. (b) `card.move` vers `archived` (ws.ts) : `rangerLaCarte(card, target, position, Date.now())` pose `rangeeTableauDeBordAt` dans la même écriture, un seul `card.upsert` ; sortir d'`archived` l'efface. La règle unique est `rangementApresDeplacement` (shared/src/en-route.ts). `store.saveCard` l'efface aussi quand la carte repart en `planned`/`running`.
7. Client : `client.rangerDansLeTableauDeBord(cartes, range, { silencieux })` range tout de suite par `pageApresCarte` (même règle que l'écho), puis bilan `bilanDeLot` (participes dans des constantes `CLE_…`). `client.moveCard` n'est optimiste que sur `column` : la carte arrive dans « Archiver » par le `card.upsert` du démon. « Tout archiver » = `cartesARangerDuTableauDeBord` sur TOUTE la colonne après `client.chargerToutTerminer()`.
8. Glisser : `usePointerDrag` d'en-route.tsx, `resoudreColonne` (`[data-colonne-en-route]` terminer/archive), `holdMs: 260` comme le tableau, appui long = menu ; la famille entière (même `cleDeFamille`, `estFinie`) est rangée ; sur téléphone le rail défile quand la carte tirée touche le bord.
9. Rattrapage : `archiverLesCartesEnLigneRestees` (archive.ts, 30 s après le démarrage) archive les cartes `to_deploy` qui portent encore un `deployedAt` : c'est un chemin automatique, elles restent dans « Terminer ».
10. Un contrôle navigateur qui a besoin de cartes archivées SANS rangement (comme après une publication) les archive par `card.move` puis les remet dans « Terminer » avec `card.rangerTableauDeBord { range: false }` : `card.move` seul les rangerait d'office.

## Pièges

Retirer l'archivage automatique PARTOUT pour obtenir un comportement de la page centrale a coincé les cartes publiées dans les projets (76c83ce2) : la page centrale a son propre état, jamais la colonne. À l'inverse, poser le rangement dans `rangerLaCarte` pour TOUS les appelants rangerait d'office les cartes d'agents et la mise en ligne : seul `card.move` passe l'instant du geste. Une carte remise « À déployer » doit perdre son rangement, sinon elle reste dans « Archiver » alors que `peutEtreRangee` la refuse. Sans la migration qui pose rangées les anciennes archives, « Terminer » reçoit des milliers de cartes. Une carte encore en Demande/Travail ne se range pas (`estFinie`). `Card.parse` ne doit jamais écrire la clé `rangeeTableauDeBordAt: undefined` (les tests de relecture comparent à l'identique). Appeler `archiveCard` dans la fin de tour AVANT `retirerLeTourVivant` échoue (« l'agent parle encore ») et laisse la branche vide derrière. `archived` n'est PAS dans `COLONNES_DE_CLOTURE` : un chemin qui y range une carte pose lui-même `doneAt`. Pour le rapport rendu qui ferme la carte, passer par `verif-cycle-de-vie-carte.mjs` (section 3). Un `pkill -f` dont le motif figure en clair dans la commande est refusé : écrire `[v]ite…`. Le contrôle `verif-en-route.mjs` peut échouer une fois sur « l'agent sans carte a le bord gauche » à 390 px (position du rail, sans rapport) : le relancer.
